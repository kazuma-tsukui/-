# サイトQAレビュー

## 準備

1. `AGENTS.md`、`REQUIREMENTS.md`、`PROJECT_STATUS.md` と起動手順を読む。
2. 対象ページ、基準URL、対応ビューポート、変更前後の範囲を決める。
3. 監査依頼では原則として大規模なコード変更を行わない。

## 主要導線を検証する

TOPから食材、カテゴリー、目的、季節／おすすめ、商品を経て個別レシピまで操作する。パンくず、戻る、TOPへ戻る、ページ下部操作、使用商品、購入リンクを実際にたどる。リンクのHTTP到達だけでなく、表示商品との意味的一致を確認する。

## 表示を検証する

- スマートフォンを優先し、文字、タップ領域、カード、材料・工程の読みやすさを確認する。
- 意図しない横スクロール、重なり、切れ、画像欠落、レイアウトシフトを確認する。
- PC代表幅でもカード配列、余白、ナビゲーション、画像を確認する。
- おすすめと商品レシピが各4件で、自動スクロールしないことを確認する。
- JavaScriptコンソール、ネットワーク失敗、既定テスト、ビルドを確認する。

認知できるUI変更後はスクリーンショットを残す。実行不能な検証は環境制約と残存リスクを示す。

## 優先度

- **Critical**: 購入・主要閲覧が不能、重大な誤商品誘導、広範囲のクラッシュ。
- **High**: 主要導線が使えない、SPで重要情報が読めない、複数ページの重大崩れ。
- **Medium**: 回避可能だが操作・理解を明確に妨げる問題。
- **Low**: 軽微な不統一や視覚上の改善。

## 報告

各問題を `優先度 / ページ・条件 / 再現手順 / 期待 / 実際 / 根拠 / 推奨対応` で記録する。確定事実と推測を分離し、重複をまとめる。修正後は対象問題と主要回帰導線を再検証し、`PROJECT_STATUS.md` を更新する。
